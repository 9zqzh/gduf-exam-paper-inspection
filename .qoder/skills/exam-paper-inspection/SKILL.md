# 试卷专项检查报告撰写

## 这个 skill 能做什么

把“查课程 → 收材料 → 逐项核查 → 写报告 → 填登记表”串成一条可核验的流程。内置：

- 4 个学期课程归属表、3 个学期试卷归档清单（2024-2025-1 至 2025-2026-2）。
- 纸质版 / 机考版两份归档目录与检查标准。
- 学院《教师试卷检查结果报告》模板排版规则。
- 命题形式核查：A/B 卷结构、题型分值、卷面要素、评分标准是否按题给分；**不判断题目与答案的对错**。
- 通用整改点库：按题型分值、评分标准结构、成绩统计和班级对比，选 3—5 条面向下一套卷/下一轮教学的改进方向；**不要求教师改动本次归档材料**。

教师只需提供姓名、确认课程、上传材料。**不要**让教师重复提供知识库已能查到的课程性质、班级、人数、归档编号。

## 先决条件

```bash
python -c "import docx, openpyxl; print('ok')"
```

缺库时执行：`python -m pip install python-docx openpyxl`。PDF 文本提取可选安装 `pypdf`；扫描件用 Read 工具按页查看。

下文用 `$SKILL_DIR` 表示本 SKILL.md 所在目录（即 `.qoder/skills/exam-paper-inspection`；换项目时用 `find . -path "*exam-paper-inspection/SKILL.md"` 定位）。所有命令在工作区根目录执行，路径含中文/空格时加引号。Windows 控制台若中文乱码，在 `python` 后加 `-X utf8`。

## 交互流程：五道闸门，逐道确认

### 第 1 步：收集教师信息

开场只问三件事：

1. 姓名（须与《课程归属表》一致）。
2. 如同学期有多门课，本次检查哪一门 / 哪个学期。
3. 试卷材料是否已准备好（文件夹路径或稍后上传）。

不要一上来就问课程性质、考试形式、班级人数——这些从知识库查。

### 第 2 步：查询并确认课程（闸门 1）

```bash
python "$SKILL_DIR/scripts/kb_query.py" --teacher "张三"
```

按结果分支：

- **命中 1 条**：用卡片式摘要展示课程名称/编号、课程性质→报告课程类型、学期、考核方式、班级与人数、教研室及主任、材料存放位置与归档编号、适用清单（纸质/机考）、数据提示（warnings）。然后明确问：**“请确认：本次检查的是这门课程吗？”**
- **命中多条**：编号列出，请教师选定“课程 + 学期”。同一教师多门课要出多份报告时，逐门处理，不要混在一份报告里。
- **未命中**：请教师核对姓名写法；可加 `--course` 关键字重试，或 `--list-teachers` 查看全部姓名。仍找不到就请教师提供“课程名称 + 学期 + 班级”，并说明知识库暂无该记录，不要凭空补课程信息。
- **命中但归档编号缺失 / 教师姓名不一致**：如实告知“需人工核对”，不要猜编号。

教师确认前，不要进入材料环节。

### 第 3 步：告知材料要求并等待上传（闸门 2）

根据 `checklist` 字段选择清单：

- `paper` → 读 `references/checklist-paper.md`
- `cbt` → 读 `references/checklist-cbt.md`

先给教师一份“本次应提交材料清单”（含份数/形式要求），再让他把文件放到：

```
试卷材料/<教师姓名>_<课程名称>_<学期>/
```

支持按班级建子文件夹，也支持直接在对话里上传。然后清点：

```bash
python "$SKILL_DIR/scripts/materials_audit.py" \
  --dir "试卷材料/张三_Java程序设计_2025-2026-2" \
  --checklist paper --classes 3 --students 167
```

`--classes`、`--students` 用第 2 步查到的数据；有实到人数时加 `--actual`。

把结果整理成三段回复：

1. **已收到**：材料名 + 文件数。
2. **还缺什么**：只列教师可控的缺失材料，说明它对应哪条检查要求、缺了会影响报告哪一部分；系统导出/纸质归档材料另起一行注明来源，不催补。
3. **未识别文件**：请教师说明归属，或确认是否属于“其他材料”。

**只有教师可控的材料才算“必需补传”**：试题、答案与评分标准、成绩单、平时成绩表、班级分析表、审核表。学校系统导出或纸质归档环节的材料（如课程级分析表、答题册、签章件）缺失时，在清点表注明来源与去向，**不要求教师补传**。无论哪类缺件，报告都不写进第四部分；确实影响某项核查时，在第一、三部分写“未提供、本项未能核验”并说明原因，交付时口头提醒。

### 第 4 步：核查结构并确认整改方向（闸门 3）

按材料逐项做，能自动算的用脚本，不能自动算的用 Read 工具看原件：

```bash
# 成绩统计（xlsx / docx 成绩单）
python "$SKILL_DIR/scripts/grade_stats.py" "材料/学生成绩单.xlsx" --json

# 提取试题、分析表文本（答案只核对是否齐全，不核对内容）
python "$SKILL_DIR/scripts/extract_text.py" "材料/期末考试试题A卷.docx"
python "$SKILL_DIR/scripts/extract_text.py" "材料/课程试卷及成绩分析表.docx"
```

核查清单：

- **成绩**：最终成绩、平时成绩、试卷成绩分别统计；人数口径一致；缺考/缓考/作弊单列。异常阈值见 `references/standards.md` 第五节。成绩数据以教务系统成绩单为准。
- **命题形式（不判对错）**：只核 A/B 卷是否齐全、题型/题量/分值结构是否一致、卷面要素是否完整、评分标准是否按题给出给分点。**不验算题目、不比对答案数值、不判断选项唯一性、不判断答案与试题知识点是否对应**。发现疑似答案问题，只在对话里请教师自行复核，不写进报告和登记表。
- **命题规范**：只写结构与形式——A/B 卷结构、分值标注、评分标准篇目与给分方式、自编卷面要素。学校统一印制的专业班级、考试日期、答题要求栏不写。
- **“两性一度”**：按 `references/two-natures-one-degree.md` 逐题登记认知层次。逐题表与占比只进核查底稿，报告正文写定性判断 + 题号/分值证据，不写百分比。**不能只看题型猜**；没有试题原文就不做逐题判断。
- **班级成绩分析表**：只核表内算术（分数÷满分=百分比、各题均分与总分、人数与占比）和跨班数值是否雷同；均值、标准差、及格率、优秀率以系统导出为准，不质疑口径。发现算术不符时作为对话提醒请教师核对，不写进第四部分。
- **课程级分析表**：学校系统导出、格式固定，不作为问题；未随电子材料提供时只在材料清点中注明。
- **平时成绩**：人数与成绩单是否一致，总评能否由表内规则解释；对不上时先请教师核对取数，作为对话提醒，不写进第四部分，也不要求补模板里没有的权重栏。
- **答题册**：纸质归档环节。电子材料未附不列为问题；只有教师提供了答题册，才核对份数与学号顺序。
- **审核表/签章**：电子稿没有手写签名、公章、日期属正常，作为纸质归档提醒，不写进报告；复选框是否勾选必须看渲染图，文本抽取结果不作数。
- **归档**：归档编号、存放位置与知识库是否一致。

**整改点怎么定**（详见 `references/issue-library.md` 与 `references/issue-triage.md`）：

不再逐题找错，而是按课程实际从通用条目中挑 3—5 条，写成“可进一步改进”的方向：

1. **看结构**：客观题与综合应用题分值、A/B 卷题型结构、评分标准是否分步给分、有无情境化/开放性题目。
2. **看数据**：期末与平时成绩差、优秀率/不及格率、平行班均值与及格率差、难度与学情是否匹配。
3. **看责任**：只写教师在下一次命题或下一轮教学中能改进的事项；系统导出、统一模板、纸质归档不写。
4. **看写法**：不写“哪道题答案错了”，不写“本次必须补做/补签/替换材料”；整改时限放在下一套 A/B 卷或下一教学周期。

报告第四部分和《试卷自查登记表》**只放这些通用整改点**，每条附一句事实依据（题型分值、评分标准结构、成绩数据或班级对比）。依据留在核查底稿，正文概括表述。**答案对错、材料缺件、签章、系统口径、模板字段一律不写报告和登记表**，需要时在交付对话中提醒。

把过程写入 `核查底稿.md`（材料清点表、成绩统计、逐题表、整改点清单及依据；全部观察按“整改点 / 提示 / 不列”标注理由）。然后向教师汇报：

- 已核验的关键数据（平均分、及格率、人数等）。
- 拟写进报告的整改点（逐条编号，写通用方向 + 一句依据）。
- 未写入报告的提醒事项（材料缺件、签章、系统口径、模板字段、疑似答案问题等）。
- 无法核验的项目。
- 最后问：**“以上整改方向是否合适？哪些需要删掉或补充？”** 提醒事项只供参考，不写入报告。

教师确认前，不要定稿。

### 第 5 步：生成报告与登记表（闸门 4）

1. 按 `references/report-spec.md` 写五个模块，正文不少于 1000 字。第四部分只写 3—5 条通用整改点，不写答案对错、材料缺件、系统导出、模板字段和纸质签章；第五部分对应写下一次命题或下一轮教学的改进措施与时限，不要求改动本次材料。
2. 两性一度只在正文写判断与题号/分值证据，**不写百分比**；逐题表与占比留在核查底稿。
3. 写 `report_payload.json`，调用：

```bash
python "$SKILL_DIR/scripts/build_report_docx.py" \
  --payload "输出_试卷检查报告/张三_Java/report_payload.json" \
  --out "输出_试卷检查报告/张三_Java/张三_Java程序设计_试卷检查结果报告.docx"
```

4. 字数不足 1000 时，脚本会非零退出。补实质分析（题型结构、数据对比、可执行的改进措施），**不要用空话凑字数**。
5. 生成自查登记表（`issues.json` 只放同一批通用整改点，提醒事项不要写进去）：

```bash
python "$SKILL_DIR/scripts/build_selfcheck_xlsx.py" \
  --payload "输出_试卷检查报告/张三_Java/issues.json" \
  --out "输出_试卷检查报告/张三_Java/张三_Java程序设计_试卷自查登记表.xlsx"
```

6. 交付前自检：字数达标；无“（填写”“TODO”“……”；报告数字与底稿一致；课程名称、姓名、班级、归档信息与知识库一致；第四部分与登记表只含教师确认过的通用整改点；没有把答案对错、材料缺件、系统口径、模板字段、纸质签章写成整改点；整改措施均面向下一套卷或下一轮教学，不要求改动本次材料。

### 第 6 步：交付

给教师文件链接，并提醒：

- 报告需教师本人签名、填写日期（脚本留空，不代签）；电子稿无签章属正常，纸质归档时补齐。
- **2026年11月4日前**按授课专业班级交给对应系主任（企业微信/微信）。
- 报告与《试卷自查登记表》一并提交。
- 单独用一段列出**未写入报告的提醒事项**（系统导出表、模板字段、纸质环节、难度建议、待教师自行复核的疑点），每条一句话，说明为什么不写进报告。

## 硬规则

1. **不编造**。数字只能来自成绩单/材料/知识库/教师明确确认。来源优先级：原件 > 知识库 > 教师口述 > 推断（推断必须标注）。
2. **先确认课程，再收材料，再写报告**。三道闸门都要得到教师明确答复。
3. **材料缺失说清楚**，不假装齐全，也不写“签字盖章齐全”而没看原件。能补的请教师补传；补不上的记为“未提供、本项未能核验”，在交付时说明，不写进第四部分。
4. **报告 ≥1000 字**，五模块齐全，整改点与措施逐条对应。
5. **整改点要有依据**：题型分值、评分标准结构、成绩统计或班级对比，能在底稿指回材料。
6. **不替教师签字**，不写“检查合格/通过”之类结论性承诺。
7. **保护学生信息**：登记表优先写学号，不写不必要的姓名。
8. **知识库是快照**。学期超出 2024-2025-1 至 2025-2026-2，或教师/课程查不到时，请教师提供最新《课程归属表》《试卷归档清单》，放入 `references/kb/` 后重跑，不要硬猜。
9. **多教师合上课程**要确认本人所授班级，报告只写本人班级。
10. **报告口吻**是教师自查，客观克制；不要出现“AI 生成”等字样。
11. **只写通用整改点**。答案对错、材料缺件、学校系统导出表及其统计口径、统一模板字段、纸质归档签章与答题册、教师评分尺度，一律不写进报告和登记表；需要提醒时在对话里说。判定规则见 `references/issue-triage.md`、`references/issue-library.md`。
12. **先核对再引用**。题型、分值、分数段、班级人数来自原件或成绩单；公式、矩阵、复选框看不清就写“未能核验”，不凭抽取结果下结论。
13. **两性一度占比不进报告正文**。正文写判断、题号和分值；逐题归类与占比留在核查底稿，教师追问时能现场解释算法。
14. **不判断答案对错**。不验算题目、不比对答案数值、不判断选项唯一性、不判断答案与试题知识范围是否对应；教师主动询问时只建议其自行复核，不写进文件。
15. **整改点面向未来**。用“还可进一步”“有待完善”表述，措施落在下一套 A/B 卷或下一教学周期；不要求补做、补签、替换本次归档材料。

## 沟通模板

**开场**

## 故障处理

- **查不到人**：核对姓名用字；`--list-teachers` 看全量姓名；再试 `--course`。
- **同一课程多学期**：默认按教师指定学期；未指定时列出让教师选。
- **归档编号对不上**：脚本会提示“教师姓名/课程名称不一致”，以人工核对为准，不强行采用。
- **成绩单识别不到列**：脚本会打印表头，用 `--total-col 关键字` 指定；仍失败就 Read 原件后手工记录，并在底稿注明。
- **扫描 PDF**：`extract_text.py` 提不出字时，用 Read 工具按页看图核对。
- **表格打印不全**：自查登记表已设横向、单页宽；若学院另有版式要求，以学院模板为准。
