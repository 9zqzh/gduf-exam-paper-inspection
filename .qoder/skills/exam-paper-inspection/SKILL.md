# 试卷专项检查报告撰写

## 这个 skill 能做什么

把“查课程 → 收材料 → 逐项核查 → 写报告 → 填登记表”串成一条可核验的流程。内置：

- 4 个学期课程归属表、3 个学期试卷归档清单（2024-2025-1 至 2025-2026-2）。
- 纸质版 / 机考版两份归档目录与检查标准。
- 学院《教师试卷检查结果报告》模板排版规则。

教师只需提供姓名、确认课程、上传材料。**不要**让教师重复提供知识库已能查到的课程性质、班级、人数、归档编号。

## 先决条件

```bash
python -c "import docx, openpyxl; print('ok')"
```

缺库时执行：`python -m pip install python-docx openpyxl`。PDF 文本提取可选安装 `pypdf`；扫描件用 Read 工具按页查看。

下文用 `$SKILL_DIR` 表示本 SKILL.md 所在目录（即 `.qoder/skills/exam-paper-inspection`；换项目时用 `find . -path "*exam-paper-inspection/SKILL.md"` 定位）。所有命令在工作区根目录执行，路径含中文/空格时加引号。Windows 控制台若中文乱码，在 `python` 后加 `-X utf8`。

## 交互流程：五道闸门，逐道确认

### 第 1 步：收集教师信息

开场只问三件事：

1. 姓名（须与《课程归属表》一致）。
2. 如同学期有多门课，本次检查哪一门 / 哪个学期。
3. 试卷材料是否已准备好（文件夹路径或稍后上传）。

不要一上来就问课程性质、考试形式、班级人数——这些从知识库查。

### 第 2 步：查询并确认课程（闸门 1）

```bash
python "$SKILL_DIR/scripts/kb_query.py" --teacher "张三"
```

按结果分支：

- **命中 1 条**：用卡片式摘要展示课程名称/编号、课程性质→报告课程类型、学期、考核方式、班级与人数、教研室及主任、材料存放位置与归档编号、适用清单（纸质/机考）、数据提示（warnings）。然后明确问：**“请确认：本次检查的是这门课程吗？”**
- **命中多条**：编号列出，请教师选定“课程 + 学期”。同一教师多门课要出多份报告时，逐门处理，不要混在一份报告里。
- **未命中**：请教师核对姓名写法；可加 `--course` 关键字重试，或 `--list-teachers` 查看全部姓名。仍找不到就请教师提供“课程名称 + 学期 + 班级”，并说明知识库暂无该记录，不要凭空补课程信息。
- **命中但归档编号缺失 / 教师姓名不一致**：如实告知“需人工核对”，不要猜编号。

教师确认前，不要进入材料环节。

### 第 3 步：告知材料要求并等待上传（闸门 2）

根据 `checklist` 字段选择清单：

- `paper` → 读 `references/checklist-paper.md`
- `cbt` → 读 `references/checklist-cbt.md`

先给教师一份“本次应提交材料清单”（含份数/形式要求），再让他把文件放到：

```
试卷材料/<教师姓名>_<课程名称>_<学期>/
```

支持按班级建子文件夹，也支持直接在对话里上传。然后清点：

```bash
python "$SKILL_DIR/scripts/materials_audit.py" \
  --dir "试卷材料/张三_Java程序设计_2025-2026-2" \
  --checklist paper --classes 3 --students 167
```

`--classes`、`--students` 用第 2 步查到的数据；有实到人数时加 `--actual`。

把结果整理成三段回复：

1. **已收到**：材料名 + 文件数。
2. **还缺什么**：逐项列出缺失材料，说明它对应哪条检查要求、缺了会影响报告哪一部分。
3. **未识别文件**：请教师说明归属，或确认是否属于“其他材料”。

**只要还有必需材料缺失，就停在这里引导补传，不要写最终报告。** 教师明确表示某项确实无法提供时，把它记为“未提供、未能核验”，写入报告第四部分，并请教师确认可以接受后再继续。

### 第 4 步：深度核查并确认发现（闸门 3）

按材料逐项做，能自动算的用脚本，不能自动算的用 Read 工具看原件：

```bash
# 成绩统计（xlsx / docx 成绩单）
python "$SKILL_DIR/scripts/grade_stats.py" "材料/学生成绩单.xlsx" --json

# 提取试题、答案、分析表文本
python "$SKILL_DIR/scripts/extract_text.py" "材料/期末考试试题A卷.docx"
python "$SKILL_DIR/scripts/extract_text.py" "材料/课程试卷及成绩分析表.docx"
```

核查清单：

- **成绩**：最终成绩、平时成绩、试卷成绩分别统计；人数口径一致；缺考/缓考/作弊单列。异常阈值见 `references/standards.md` 第五节。
- **命题规范**：A/B 卷、卷面要素、大纲覆盖、题量分值、答案与评分标准。
- **“两性一度”**：按 `references/two-natures-one-degree.md` 逐题登记认知层次并算占比。**不能只看题型猜**；没有试题原文就不做逐题判断。
- **分析表**：四段（试卷情况、改进措施、考试结果分析、改进教学建议）是否各约 200 字；数据是否与成绩单一致。
- **平时成绩**：是否注明分数来源；人数与成绩单是否一致。
- **答题册**：份数 vs 实到人数；是否按学号排序（抽查）。
- **审核表/签章**：签字、盖章是否完整（看扫描件）。
- **归档**：归档编号、存放位置与知识库是否一致。

把过程写入 `核查底稿.md`（材料清点表、成绩统计、逐题表、问题清单及证据）。然后向教师汇报：

- 已核验的关键数据（平均分、及格率、人数等）。
- 发现的问题（逐条编号，带位置与证据）。
- 无法核验的项目。
- 最后问：**“以上问题是否属实？需要补充或修改吗？还有需要写进报告的问题吗？”**

教师确认前，不要定稿。

### 第 5 步：生成报告与登记表（闸门 4）

1. 按 `references/report-spec.md` 写五个模块，正文不少于 1000 字。
2. 写 `report_payload.json`，调用：

```bash
python "$SKILL_DIR/scripts/build_report_docx.py" \
  --payload "输出_试卷检查报告/张三_Java/report_payload.json" \
  --out "输出_试卷检查报告/张三_Java/张三_Java程序设计_试卷检查结果报告.docx"
```

3. 字数不足 1000 时，脚本会非零退出。补实质分析（题目证据、数据对比、具体整改），**不要用空话凑字数**。
4. 生成自查登记表：

```bash
python "$SKILL_DIR/scripts/build_selfcheck_xlsx.py" \
  --payload "输出_试卷检查报告/张三_Java/issues.json" \
  --out "输出_试卷检查报告/张三_Java/张三_Java程序设计_试卷自查登记表.xlsx"
```

5. 交付前自检：字数达标；无“（填写”“TODO”“……”；报告数字与底稿一致；课程名称、姓名、班级、归档信息与知识库一致；问题与教师确认过的一致。

### 第 6 步：交付

给教师文件链接，并提醒：

- 报告需教师本人签名、填写日期（脚本留空，不代签）。
- **2026年11月4日前**按授课专业班级交给对应系主任（企业微信/微信）。
- 报告与《试卷自查登记表》一并提交。

## 硬规则

1. **不编造**。数字只能来自成绩单/材料/知识库/教师明确确认。来源优先级：原件 > 知识库 > 教师口述 > 推断（推断必须标注）。
2. **先确认课程，再收材料，再写报告**。三道闸门都要得到教师明确答复。
3. **材料缺失先说清、先补传**，不能假装齐全，也不能写“签字盖章齐全”而没看原件。
4. **报告 ≥1000 字**，五模块齐全，问题与整改逐条对应。
5. **问题要有位置和证据**：哪份材料、哪道题、哪个环节、差多少。
6. **不替教师签字**，不写“检查合格/通过”之类结论性承诺。
7. **保护学生信息**：登记表优先写学号，不写不必要的姓名。
8. **知识库是快照**。学期超出 2024-2025-1 至 2025-2026-2，或教师/课程查不到时，请教师提供最新《课程归属表》《试卷归档清单》，放入 `references/kb/` 后重跑，不要硬猜。
9. **多教师合上课程**要确认本人所授班级，报告只写本人班级。
10. **报告口吻**是教师自查，客观克制；不要出现“AI 生成”等字样。

## 沟通模板

**开场**

> 老师您好，我来协助您完成试卷检查报告。请先告诉我您的姓名（与《课程归属表》一致）；如果这学期有多门课，请说明本次检查的课程或学期。

**课程确认**

> 我查到：2025-2026-2学期《Java程序设计》（173121003），学科基础必修课，25清远计算机科学与技术1—3班共167人，闭卷考试，材料在行政楼202试卷档案室（归档编号清E009、清E010、清E011）。请确认这是本次要检查的课程吗？

**材料缺失**

> 目前已收到试题、答案、成绩单等 6 项，还缺：①学生平时成绩登记表；②课程试卷及成绩分析表；③试卷审核表。请把文件放到 `试卷材料/…` 或直接上传。补齐后我再做逐项核查；如果某项确实无法提供，请告诉我，我会在报告中如实注明“未提供、未能核验”。

**核查确认**

> 核查发现 3 个问题：……。请确认是否属实、是否需要补充；确认后我按学院模板生成报告和自查登记表。

## 故障处理

- **查不到人**：核对姓名用字；`--list-teachers` 看全量姓名；再试 `--course`。
- **同一课程多学期**：默认按教师指定学期；未指定时列出让教师选。
- **归档编号对不上**：脚本会提示“教师姓名/课程名称不一致”，以人工核对为准，不强行采用。
- **成绩单识别不到列**：脚本会打印表头，用 `--total-col 关键字` 指定；仍失败就 Read 原件后手工记录，并在底稿注明。
- **扫描 PDF**：`extract_text.py` 提不出字时，用 Read 工具按页看图核对。
- **表格打印不全**：自查登记表已设横向、单页宽；若学院另有版式要求，以学院模板为准。
